# jho: AeroCast (Challenge #5) pipeline, models, dashboard and audit

Everything here is self-contained. Teammates' files at the repo root are unchanged. The pipeline only reads the shared IEM cache in `../data/weather/raw` and the raw `../data/Flight_Data_With_Weather_Final.csv`.

| Path | What |
|---|---|
| `RUBRIC_AUDIT.md` | Requirement-by-requirement and rubric audit, blockers, defects fixed, next steps |
| `aerocast_data/` | Download (BTS, METAR, TAF, NOAA Storm Events) -> leakage-safe build -> LightGBM + baselines -> Streamlit dashboard |
| `data_cleaning.ipynb`, `weather_download.ipynb` | Teammate notebooks with the CLAUDE.md fixes (UTC weather timing, true as-of 3-12 h join). Inputs from `../data`, outputs to `jho/data` |
| `data/` | Outputs of the fixed notebooks (`flight_weather_features_3to12h.csv` is regenerated by `weather_download.ipynb`, not committed) |

## Run (needs internet access to transtats.bts.gov, mesonet.agron.iastate.edu, www.ncei.noaa.gov)

```bash
cd jho/aerocast_data
pip install pandas pyarrow requests airportsdata lightgbm scikit-learn streamlit plotly pytest
python -m pytest -q tests
python run_all.py --start 2024-01 --end 2025-07 --airports ATL DFW
streamlit run dashboard.py
```

The optional Claude summary in the dashboard reads `ANTHROPIC_API_KEY` from the environment. Never commit a key.
